| **写盘时机** | `services/document-service.ts` 的 `SavePipeline`（2026-11-09 起**由 `DocumentSession` 持有**：同一文件一条管线，视图不再各自持有） | **照搬 Obsidian `TextFileView`**（2026-11-07）：内容变更后 **2 秒防抖**写盘（`AUTO_SAVE_DEBOUNCE_MS = 2000`，即官方 `requestSave` 的固定值）；关闭视图 / 切换文件 / 插件卸载时**立即保存**。**没有「自动保存」设置项**（已删）、**没有「连续失败挂起」**（P1b 已删，写失败只报「未保存」并在下一次编辑重试）；外部写入的处理由 `DocumentSession` 单点承接（写盘前发现磁盘正文已变 ⇒ 放弃写盘 → 重载 → 草稿留作一条撤销，见「同文件多视图的同步」行）。写入一律 `Vault.process`（原子读改写；运行时缺失时回退 `cachedRead` + `modify`）：文件头**及其与正文之间的空行**（`splitFrontmatter().gap`）恒取磁盘当前值、正文取本视图序列化结果——编辑不会吃掉那一行空行（K176）。**换行形态随文件**（2026-11-11 实机）：`markLoaded` 从原样正文探测 CRLF/LF（`loadedEol`），序列化按同一形态输出——CRLF 文件编辑一行不会把其余正文改成 LF；行尾两空格（硬换行）随 `mdRaw` 逐字回写。**关闭/切文件顺序是契约**：`closeInlineEditor` 必须早于 `commitsArmed = false`，否则最后一次内联编辑被 `commitSession` 静默丢弃。**纯浏览不写盘**：`markLoaded` 在加载完成、引擎建好后记下序列化正文，本轮与它逐字相同即跳过；本会话写过盘之后撤销回加载态必须写回 `loadedRawBody`（加载时原样正文）。**收尾自检**只对真的写过盘的自动保存轮次做（`reconcile`，每路径最多 3 次），显式保存不补排。判据只看**正文**（`loadedBody`），文件头不参与。K156 / K158，回归 `tests/save-pipeline.test.ts` |
| **`data.json` 里 `viewState` 的写盘判据**（按文件视口与外观偏好） | `services/view-state.patch` + `services/engine-controller.persistViewport` | **只写变化**（2026-11-11）：`patch` 按序列化结果逐字比较，与本条相同即不排写盘（关掉视图时会读一次引擎视口，「没动过就关」是常态）；关闭/切换/切回 Markdown 时若视口**仍是打开时自动设置的那个**（`viewport.defaultSignature` 命中、且未恢复过保存视口）**不写**——默认视口是当场按容器与内容算出来的，落盘只等于把当时的窗口尺寸固化进 data.json（实机：96 张导图 / 39 条状态 / 26 KB，其中 23 条属此类）。**不做**「等于全局默认就省略」：`themeStyle` / `lineStyle` 的「显式切过」与「从没切过」语义不同（前者保持原值、后者跟随未来默认变更，见「边框」行）；`view.transform` 与 `state` 数值重复但由 vendor `setTransformData` 独立消费，**不删**。**调用时机是契约**：`persistViewport` 必须排在 `invalidateInit` / `destroyInstance` **之前**（两者 `viewport.reset()` 会清空判据；2026-11-11 实机首轮即因此失效，`onUnloadFile` / `onClose` 已按此排序），且单测必须复现真实关闭顺序。**重算窗口不重读 store**：`defaultSignature` 非空即「已在默认视口模式」，`restoreOrFitViewport` 只重算默认视口、不再读保存值——否则同一文件另一视图刚写入的视口会把本视图带跑（实机：两视图并排，关掉平移过的那侧，另一侧跳过去）；**已恢复保存视口时 150 ms 兜底直接收手**（2026-11-11 静态审查：savedView 分支会把 `defaultSignature` 置 null，旧兜底据此误判成「可以再读一次」）。**两个已裁决不做的项**：不记忆「没动过的默认视口」（下次重算，出界由可见性兜底）、不清理历史默认视口条目（判定需逐图重建引擎，误删丢位置）。K195，回归 `tests/view-state.test.ts` / `tests/engine-controller.test.ts` |
| **同文件多视图的同步**（两个 leaf 打开同一张导图） | `services/document-session-registry` + `services/document-session`（组合根 `main.ts` 的 `vault.on('modify')` → `registry.onModify`） | **Level B（2026-11-09，替换 K177 的「后关闭者胜」）**：同一文件一个 **`DocumentSession`**——一棵权威树 + 一条单游标撤销线 + 一条保存管线；视图引擎只是只读投影。**编辑**：发起视图在 `data_change` 里 `commit(snapshot, this)`，会话合入历史后广播给其它视图（**跳过 origin**；小图 0 ms、>600 节点 60 ms 合并，K185）；应用走 `engine/mindmap-snapshot.applySessionSnapshot`（= `updateData` 去掉 `addHistory`：不进历史、不发 `data_change`，故不会重复排保存 / 守卫 / 改名，K181）。**撤销/重做**：`view-hotkeys` / 竖栏 / 右键 / 语法守卫全部走会话（视图侧方法名必须是 `undo` / `redo`，K189），广播给所有视图。**编辑期就地归一**（层级语法守卫只改引擎 md 字段、不发 `data_change`）经 `session.updateCurrent` 同步权威树——替换当前快照、**不新增历史**（K188）。**保存**：同一文件只由会话排（2 s 防抖、关闭 flush、无差异跳过、未记基线不写盘，K183）。**外部写入**（对齐官方冲突分支）：写盘前发现磁盘正文变了 ⇒ **放弃写盘**（`onExternalAbort`）→ 会话重载 → 新树追加为一条历史（Ctrl+Z 回到草稿）→ 有草稿提示一次、无草稿静默（K182）。**重命名**只迁移注册表键，视图不重建（K184）。**过期提交**（2026-11-09 实机）：提交视图尚未应用最新版本时，其整树快照会覆盖另一侧的编辑 ⇒ `commit` / `updateCurrent` 拒绝并 `notifyStaleCommit` 提示一次，由广播刷回权威树；**已知差异**：不做树级合并（保 `mdRaw` 逐字）、不做跨进程（K194） |
| **状态栏的保存状态**（`保存中…` / `已保存` / `未保存`） | 判据 `services/document-service.ts` 的 `isAtLoadedState`；出口 `SavePipeline.schedule()` 的 `ScheduleOutcome`（`scheduled` / `noFile`）+ `onSaved` / `onSaveError` → `features/view.setSaveState` → `services/status-bar.showSaveState` | 「内容是否已落盘」只有**一份判据**：本轮序列化 vs `markLoaded` 基线（只比正文）。`schedule()` 返回 `scheduled`（报「保存中」）/ `noFile`（加载中/已卸载，什么都不报）；写盘成功含无差异跳过 → `onSaved`（「已保存」）；写盘异常 → `onSaveError`（「未保存」，常驻到下一次成功）。状态栏是插件级共享元素，**只由活动视图写**（`getActiveViewOfType`），换文件复位 `idle`、切语言按当前状态重推。K166，回归 `tests/save-pipeline.test.ts` / `tests/view-status.test.ts` |
| **撤销链的起点**（第 0 条历史快照） | `engine/mindmap-history.seedInitialHistory` | 在 `createMindMap` 里挂**一次性的** `node_tree_render_end`，首帧渲染落地时播种（`if (!isReadonly)`）。**时机必须是渲染之后**：创建瞬间的树还没被引擎规范化（`expand` 等字段渲染期才补），此刻播种会与渲染后那条快照内容不同 ⇒ 多出一条「按 Ctrl+Z 毫无反应」的历史（实测打开后 `2 条 / idx 1`）。**必须用非防抖的 `originAddHistory`**：`addHistory` 被引擎以 `addHistoryTime`（100ms）包装过，播种若被防抖会与紧随的编辑合并成一条，第 0 步又变成「编辑后」。缺它则引擎历史为空、`activeHistoryIndex` 停在 0，`Ctrl+Z` 因 `index - 1 < 0` 静默空转 ⇒ **本次会话的第一次编辑撤不掉、也永远回不到打开时的原样**（2026-11-02 实机：勾复选框 / 内联改字后撤销无反应）。回归 `tests/engine-history-limit.test.ts`（K160） |

## UI 组件边界（K207）

工具栏和搜索栏的骨架、局部事件及样式内聚于 `ui/toolbar` / `ui/search`。`features/view-toolbar` 提供按钮分组与业务动作，`features/view-search` 负责引擎搜索/防抖/跳转；组件不引入 features/services/engine。组件重建前与视图关闭时显式销毁，所有 DOM 监听和焦点任务由所属组件清理，搜索防抖由业务适配清理。CSS 源旁置但仍构建成一个发布资产，宿主的加载方式不变；节点自绘内联样式参与测量与导出，本批不迁移它们。


## 节点编辑组件与提交管线（K208）

`features/node-inline-editor` 管理编辑会话与引擎/节点访问，`ui/node-editor` 内聚文本框 DOM、按键/点击、测量与内联样式；UI 不访问引擎。会话与组件各自持有 `EventBinder`，结束编辑立即清理引擎和 DOM 监听，恢复节点 visibility。共享写回唯一源 `features/node-content-write`，原编辑模块仅保留仍有调用的单项写回兼容出口；业务调用方直接依赖提交模块，避免任务/配色/联系通过编辑器加载 UI。按键纯语义在 domain，已有保存/撤销/文档会话契约保持不变。
