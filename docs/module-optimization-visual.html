MindMap Studio · 模块组合优化可视化

基于 src/ 实测（60 个 .ts）的调研报告可视化 · 2026-09-14
结论：当前分层已健康（L0 domain 零依赖、引擎不引 obsidian、features 经窄接口触达）。 功能呈现的天花板不在"混乱"，而在两道具体接缝 + 一个手动组合根。 最高杠杆两步：P1 用注册中枢+服务容器替换手动接线（零行为风险），P2 用"节点内容子系统"兑现内联可点链接/富文本（§5 选项 1/7）。

① 当前模块组合（实测架构）

features 呈现层 services 横切层 engine 渲染层 domain/markdown/links/media 基础层 呈现天花板接缝

② 功能呈现的两道"天花板"接缝

接缝 A
仅首个链接内联、URL 仅图标（icon-only）。
解析层把非首个链接降级为尾随文本：md-outline.ts:421-422,444-445,297、 md-serialize.ts:8「文本 + 行尾单链接 token」。→ 一行多 [[链接]] 不内联可点。
接缝 B
节点自定义内容只能排在文字之前、且必须是 <svg> 根。
engine/mindmap.ts:196 注入 createNodePrefixContent；:88-89 注释"el 被放进 foreignObject，必须是 <svg> 根，裸 <g> 不渲染"。→ 无内联富文本 HTML。
两处即"更优秀功能呈现"的核心突破口，对应 §5 选项 1 / 7 / 2。

③ 6 条模块组合优化方向
