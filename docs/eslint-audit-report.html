三、发现明细

F1 · warning已修复 manifest.json：description 含白名单外字符「:」

规则源（validate-manifest.ts）对 description 有 4 项子检查，实测仅字符白名单不满足：

子检查要求实测
长度10–250 字符173 ✅
首字母大写/^[A-Z]/"Mind…" ✅
句号结尾endsWith(".")"…export." ✅
字符白名单[A-Za-z0-9\s.,!?'"-]含 :（"Markdown: edit"）❌

修复方案（修补轮已按此落地）：把冒号改为句号，例如：

"Mind map rendering for Markdown. Edit .mindmap.md as a mind map, with Markdown outline round-trip, native wikilinks and images, layouts, search, auto-arrange and PNG export."

说明：冒号限制是本插件对 Obsidian 提交规范的启发式检查（warning 级），不影响当前插件运行与提交流程，是否调整由项目自行决定。另注：id / name / author 等字段的必填键、类型、禁词（obsidian / plugin）检查全部通过。

G1 · 缺口已接入 manifest.json 未接入 lint 流程

当前 npm run lint（CI 同）永远不会执行 obsidianmd/validate-manifest——清单结构回归（如误删必填键、id 混入 "plugin" 禁词）不会被发现。这是官方插件推荐的已知边界（recommended 配置未内含 manifest 块），需项目在 eslint.config.mts 自行补一个块，例如：

import tseslint from 'typescript-eslint';

{
  files: ['manifest.json'],
  plugins: { obsidianmd },
  languageOptions: {
    parser: tseslint.parser,
    parserOptions: { extraFileExtensions: ['.json'] },
  },
  rules: { 'obsidianmd/validate-manifest': 'warn' },
}

（配置中已有的 allowDefaultProject: ['manifest.json'] 是为 type-checked 规则准备的，不解决"文件没被拾取"的问题。）

修补轮落地：eslint.config.mts 已新增 files: ['manifest.json'] 块（import { parser } from 'typescript-eslint' + obsidianmd/validate-manifest: 'warn'），复测 lint 文件数 78→79、0 错误 / 0 警告。

G2 · 缺口已接入 LICENSE 未接入 lint 流程

obsidianmd/validate-license 依赖插件内置的 plain-text parser（lib/plainTextParser.ts），该 parser 未被导出、也未挂入 recommended 配置，需项目自备等价 parser（约 40 行，将每行作为 Line token 产出 Program）+ files: ['LICENSE'] 块。当前 LICENSE 为标准 MIT 文案（"Copyright (c) 2026 Winter Mosquito"），规则实测零告警；接入后可防止未来误换回官方样板版权行（Dynalist Inc.）或年份过期。

修补轮落地：新增 scripts/plain-text-parser.mjs（与官方 plainTextParser.ts 等价的行级 parser，scripts/ 本就在 globalIgnores 不参与 lint）+ eslint.config.mts 新增 files: ['LICENSE'] 块（obsidianmd/validate-license: 'warn'）。复测 lint 文件数 79→80、0 错误 / 0 警告；并以 Dynalist Inc. 样板内容做阳性对照——规则准确抓出「年份过期 + 持有人未改」2 条警告，证明管线真实有效。
